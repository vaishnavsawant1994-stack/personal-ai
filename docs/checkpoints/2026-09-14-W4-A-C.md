## Workstream A — explainable memory retrieval

The current batch adds a stable retrieval explanation attached only to memories that were actually selected. The explanation records memory identity/type/subject, source and source timestamp, confidence, verification, sensitivity, source age, semantic score where available, existing salience score/decay, graph relationship count, active/historical state, contradiction/supersession state, selection reason, retrieval query, use timestamp and evidence references.

Security behavior:

- `NEVER_STORE` is excluded before ranking/usage.
- authenticated owner inspection can pre-filter allowed sensitivity classes before selection;
- a memory that was not selected for the supplied query receives no synthetic retrieval claim;
- deleted memories cannot receive retrieval explanations.

Relationship contribution is currently reported as `0.0` because relationships are inspectable context but are not part of the validated numeric salience formula. This avoids falsely claiming an influence on rank that does not exist.

The separate Memory inspection dialog gains a `Why Retrieved` tab without altering frozen Home V1 or the AI Core visual architecture.

## Workstream B — Knowledge versioning and provenance

Knowledge storage now uses additive SQLite migrations for immutable document versions and lineages:

- lineage ID, version number, current/superseded state and ingestion time;
- changed same-document uploads create a new version instead of silently destroying old content;
- retrieval defaults to current versions;
- historical search is explicit;
- owner-visible version history;
- authorized version deletion and complete lineage deletion;
- current-version promotion when the current version is deleted;
- citations include document ID, lineage, version, source, checksum, ingestion time, page/chunk and structured location;
- PDF text extraction preserves page-level provenance.

The checksum index migration is deliberately non-unique so a valid later version may revert to bytes that appeared in a historical version. Exact-current checksum deduplication remains enforced by application logic for backward compatibility.

## Workstream C — bounded image/OCR ingestion

Image ingestion declares PNG/JPEG/WebP/TIFF support and enforces file, dimension, pixel and frame limits. Images are verified with Pillow and re-encoded as RGB PNG before storage to strip ungoverned source metadata.

OCR is provider-injected only. With no approved provider the operation fails closed with a clear `OCR unavailable` state. Private images are not sent to a provider marked external unless explicit policy permits it. Deterministic OCR test doubles retain block/page coordinates in citation location metadata.

This is **IMPLEMENTED/PARTIAL** only. It is not production-ready or representative-document qualified, and no live paid/external OCR service is required or claimed.
