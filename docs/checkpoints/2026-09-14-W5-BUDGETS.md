## Root causes repaired

The prior workflow engine already had durable checkpoints, retries/timeouts, cancellation and owner/device/session authority, but workflow resource limits were not a durable run policy. Concurrency was effectively bounded only by in-process worker pools, actual model/tool dispatches had no workflow-scoped durable accounting, and a timeout/crash did not have a durable dispatch identity proving whether an external operation was safe to repeat.

Coordinator testing also found a recovery-specific bug while developing W5: releasing a concurrency slot for restart initially persisted the release reason as a permanent budget stop reason, preventing legitimate owner-reviewed recovery. Release bookkeeping is now separate from terminal budget denial.

## Durable workflow policy

Every workflow now has an additive `policy_json` with bounded values for:

- maximum runtime, steps, retries and concurrent runs;
- maximum model and tool calls;
- optional input/output/total token and cost budgets;
- approval threshold;
- optional absolute execution deadline;
- cancellation grace period;
- owner-override permission.

Existing workflow rows migrate through secure defaults without destructive rewriting.

## Durable accounting and concurrency

A separate SQLite budget ledger persists the run policy snapshot, start/deadline, durable concurrency reservation, completed steps, retries, actual model/tool dispatch counts, provider-confirmed usage, explicitly estimated input usage, approval waits, cancellation state, stop reason, release state, redacted budget decisions and durable dispatch records.

Concurrency reservation and reacquisition use `BEGIN IMMEDIATE`, so independent engine/manager instances and simultaneous threads cannot race past `max_concurrent_runs`.

Approval-wait runs retain their concurrency slot. Restart/recovery-required runs release it and must atomically reacquire it before owner-reviewed resume.

## Actual model/tool boundary enforcement

Workflow budget context is propagated into the actual provider HTTP boundary and actual tool handler boundary. Interactive non-workflow use is unchanged.

Each real provider attempt consumes a model-call unit. Each real tool-handler dispatch consumes a tool-call unit. Durable dispatch identities include run, step, attempt, phase, action identity and ordinal. A previously recorded/uncertain dispatch is never silently repeated; it becomes recovery review.

Provider usage is recorded as confirmed only when the provider returns evidence. OpenAI-style `usage`, generic `usage_metadata` and Gemini-style `usageMetadata` are recognized for confirmed token accounting. Input preflight estimates remain separately labeled estimates. Cost is never described as confirmed unless an explicit provider cost value exists.

## Trusted actions, override and Emergency Stop

The existing Trusted Action Core remains authoritative for owner/device/session/reauth/security-epoch/tool/parameter/destination/data-classification and one-use approval semantics. Workflow `approval_threshold` can make that existing approval path stricter; it does not bypass it.

Owner budget override is disabled by default. When enabled, it requires the original bound owner/device/session plus recent reauthentication and results in recovery review rather than automatic execution.

Emergency Stop now also halts active/waiting W5 runs, releases their durable concurrency reservations, clears workflow approval pointers and records recovery evidence. Clearing Emergency Stop does not resurrect an invalidated permit; recovery still requires reviewed resume and the Trusted Action Core's current security epoch.

## Owner-facing status

Workflows and Activities expose limits, current consumption, remaining budget, deadline, retries, model/tool calls, confirmed versus estimated usage, concurrency position, stop reason and approval/recovery/cancellation state. This is added without redesigning Home V1 or the AI Core.

Safe states include Workflow limit reached, Maximum runtime reached, Concurrent run limit reached, Model-call limit reached, Tool-call limit reached, Token/cost budget unavailable, Waiting for approval, Recovery review required, Cancelled by owner and Emergency Stop active.
